Недоделанное видео в «Истории»

A · часыB · процентыC · по кнопкеD · строка сверхуВыбрать

Что случилось

Ночная запись 29 окт., 18:45 → 30 окт., 09:10 (14,5 ч, 702 МБ) так и осталась сырым потоком go2rtc: 2,24 млн фрагментов, по одному на кадр. После «Стоп» приложение начало её подготавливать (звук в AAC, обычный MP4), но закрылось на середине. Больше её никто не доделывал. Теперь каждый раз при открытии «Истории» три загрузки разом читают этот файл: длительность, превью и ещё одна. Это около 3 минут на полтора ядра — те самые 48% CPU.

Во всех вариантах одинаково

  • Приложение узнаёт недоделанный файл по заголовку (после moov идёт moof) за миллисекунды и не открывает его через AVFoundation: не загружает длительность, не делает превью, не создаёт плеер.
  • Длину пока показывает приблизительно, по времени создания и изменения файла: ≈ 14:25:00. Точная появится, когда файл будет готов.
  • За раз подготавливается только один файл, в фоне, с низким приоритетом. Брошенные временные файлы (tmp/*.m4a) удаляются при запуске.
  • У готовых файлов длительность запоминается на диске, поэтому «История» не перечитывает их при каждом открытии.
  • Обычная запись после «Стоп» готовится за секунды и выглядит как сейчас. Разница видна только на длинных и брошенных файлах.
