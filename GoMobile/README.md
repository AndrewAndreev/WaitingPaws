# Встроенный go2rtc

[go2rtc](https://github.com/AlexxIT/go2rtc) 1.9.14 с патчами Waiting Paws: в iPhone и Mac он собран в
`Frameworks/Go2RTC.xcframework` (gomobile) и работает внутри процесса приложения, на Windows — отдельный `go2rtc.exe`
(`GoMobile/desktop/main.go`, сборка — `Desktop/scripts/build-go2rtc.mjs` с теми же патчами, см.
[Desktop/README.md](../Desktop/README.md)). Как приложение им пользуется — в [ARCHITECTURE.md](../ARCHITECTURE.md).

## Сборка фреймворка

Один раз и после обновления версии go2rtc:

```bash
brew install go xcodegen
go install golang.org/x/mobile/cmd/gomobile@latest && ~/go/bin/gomobile init
./GoMobile/build.sh
```

Скрипт клонирует go2rtc нужного тега в `GoMobile/build/`, добавляет пакет `GoMobile/mobile` (повторяет `main()`
go2rtc с модулями api, ws, streams, http, rtsp, webrtc, mp4, hls, mjpeg, xiaomi, ограничивает Go двумя ядрами),
накладывает патчи ниже и собирает `Frameworks/Go2RTC.xcframework` для iOS, симулятора и macOS (~16 МБ в iOS-сборке).
Рядом пишет `Frameworks/Go2RTC.source` — git-дерево `GoMobile/`, из которого собран фреймворк; `Tools/release.sh`
сверяет его с тегом выпуска.

Без фреймворка проект тоже собирается (`#if canImport(Go2RTC)`), но встроенный режим будет недоступен — приложение
предложит указать свой сервер.

Чтобы добавить модули go2rtc во встроенную сборку, допишите их `Init()` в `GoMobile/mobile/mobile.go` и пересоберите
фреймворк.

## Патчи

Копии файлов go2rtc (`xiaomi-cs2/conn.go`, `mp4/muxer.go`) сделаны с v1.9.14: скрипт откажется собирать с другой версией,
пока их не перенесут. Остальные правки — `sed` в `build.sh` с проверкой, что замена применилась.

* **Транспорт Xiaomi CS2** — своя копия `GoMobile/xiaomi-cs2/conn.go`:
  * UDP-сокет с буфером приёма 4 МБ: системных 768 КБ не хватало на всплеск ключевого кадра, а каждая потеря
    датаграммы — это стоп картинки до повтора от камеры;
  * 2048 пакетов не по порядку вместо 250 (пока ждём потерянный, остальные подтверждаются, и камера не шлёт их
    повторно), очередь кадров 1000 вместо 100, полная командная очередь не рвёт соединение, без спама
    «cs2: unknown msg»;
  * по умолчанию просим UDP (`transport=tcp` в источнике — просить TCP), и это пожелание, а не требование: камера,
    которая его не предлагает, через ≤2 с подключается по своему выбору. C302 сама выбирает TCP, а там потерянный
    в Wi-Fi пакет держал весь поток 1–1,5 с до повтора; по UDP CS2 восполняет потерю за миллисекунды (одна камера,
    одни минуты: самая длинная пауза 0,2–0,45 с по UDP и 1,2–1,45 с по TCP);
  * камере, которой плохо по UDP (потерянный пакет держит видео 3 с), соединение пересоздаётся по TCP, и час она
    получает TCP (`cs2: UDP to … is struggling …`): на медленном Wi-Fi (C200: пинг ~200 мс) камера пересылает
    пакеты раньше, чем до неё доходят наши подтверждения, треть трафика — повторы, и связь проседает до обрыва;
    TCP подстраивается под канал;
  * в журнал — транспорт при подключении и раз в 30 с тайминг кадров (см. «Диагностика» в
    [DEVELOPMENT.md](../DEVELOPMENT.md)).
* **Очередь кадров на каждого зрителя** — 256 вместо 64 (`pkg/core/track.go`): зритель, отставший на ~3 с, терял
  кадры и стоял до следующего ключевого.
* **Запись в реальном времени** — своя копия `GoMobile/mp4/muxer.go` для `/api/stream.mp4` держит каждый кадр до
  прихода следующего и даёт ему длительность до него, так что пауза источника (кадры, которые камера не отправила,
  переподключение) остаётся в файле стоп-кадром на своём месте. В оригинале любая пауза длиннее 1 с сжимается до
  1 мс: на C200 со слабым Wi-Fi картинка за 4 минуты убежала от звука и часов камеры на 32 с, за здоровые 45 минут —
  на 6 с. Живой плеер (MSE) по-прежнему сжимает паузы, ему стоп-кадр на секунды не нужен.
* **Звук Xiaomi по часам камеры** — `GoMobile/xiaomi-miss/audioclock.go`, подключается `sed`-ом в `producer.go`.
  В оригинале это счётчик пакетов с нуля при каждом подключении, и после переподключения или потерянных пакетов звук
  ушёл бы вперёд картинки. `RecordingFinalizer` при перекодировании в AAC возвращает такие паузы тишиной: декодер
  их выбрасывает.
* **HEVC в MP4** пишется с тегом `hvc1` вместо `hev1` (`pkg/iso`): Apple читает только `hvc1`; без этого Фото
  отвечали ошибкой 3302, а плеер не открывал запись.
* **Добавки к Xiaomi** — файлы из `GoMobile/xiaomi/` копируются в `internal/xiaomi` go2rtc:
  * `/api/xiaomi/miot` читает и меняет настройки камеры (ночной режим и т. п.) через Mi Cloud — только камеры из
    настроенных потоков (тот же аккаунт и `did`), иначе 403: токен аккаунта достаёт до любого устройства Mi Home.
    Тесты: `go test ./internal/xiaomi -run Miot`;
  * `/api/xiaomi/logout` забывает аккаунт;
  * `/api/xiaomi/cameras` перечисляет камеры своих и общих домов, как Mi Home и интеграция Xiaomi для Home Assistant:
    `/v2/homeroom/gethome` с `fetch_share`, затем `/v2/home/device_list_page` по `dids`. Upstream `/api/xiaomi`
    спрашивает только `device_list_page` без параметров и общих домов не видит;
  * `POST /api/xiaomi/motor?src=<поток>&operation=<1 влево|2 вправо|3 вверх|4 вниз>` — один шаг поворотной камеры.
    Это команда MISS `0x112 {"operation":N}`, как в Mi Home. В go2rtc v1.9.14 она объявлена, но не отправляется:
    отправку добавляет `GoMobile/xiaomi-miss/motor.go`. Шаг идёт по сессии камеры работающего потока (у этих камер
    одна P2P-сессия), до неё эндпоинт добирается через `Stream.Conns()` из `GoMobile/streams/waitingpaws.go`
    (копируется в `internal/streams`). Ответы: 204 — шаг отправлен, 409 — потока нет, он не запущен или его камера
    не поворачивается, 502 — камера не приняла команду. Запрос того же вида, что в upstream PR AlexxIT/go2rtc#2531.
    Тесты: `go test ./internal/xiaomi -run Motor`.

  Сторонний go2rtc их не знает — тогда режимы камеры не показываются, выход недоступен, камеры общих домов не
  находятся, а поворот отвечает «обновите Waiting Paws».
* **Защита API** — `GoMobile/api/waitingpaws.go` копируется в `internal/api`:
  * Host — только IP или localhost (`.local` — только клиентам из LAN с паролем: имя mDNS любой в сети может
    направить на 127.0.0.1), чужой Origin браузера — 403, в том числе для WebSocket;
  * `/api/exit`, `/api/restart`, запись конфига и `/api/preload` выключены;
  * потоки меняются только через `/api/streams`: в остальных запросах `name` и `src` с адресом источника — 403
    (плееры go2rtc создают и перенаправляют поток по `name` + `src`, а `<img>`/`<video>` браузер шлёт без Origin);
  * клиентам из LAN недоступны конфиг, журнал, аккаунты Xiaomi, изменение потоков и запись в поток (`dst`,
    `/api/stream`); режимы и поворот камеры — можно: так их меняет подключённый iPhone;
  * пароль для LAN, который меняется без перезапуска, и `Relisten` после приостановки на iOS;
  * `log.Fatal` при ошибке слушающего сокета заменён на ошибку в журнале: иначе приложение закрывалось бы при
    возврате из фона.

## Тесты

```bash
cd GoMobile/build/go2rtc
go test ./pkg/mp4 ./pkg/xiaomi/miss ./pkg/xiaomi/miss/cs2
go test ./internal/api -run WaitingPaws   # защита API
go test ./internal/xiaomi -run 'Motor|Miot'   # поворот и настройки камеры
```

## Лицензии

`GoMobile/licenses.sh` пересобирает `App/Resources/Legal/Acknowledgements.txt` по модулям, которые реально попадают во
встроенный go2rtc (go2rtc, его Go-модули и стандартная библиотека Go). Запускайте после `build.sh`, когда меняется
go2rtc или его модули.
